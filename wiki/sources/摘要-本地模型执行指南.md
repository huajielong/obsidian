## 核心摘要

同一台本机的本地大模型运行手册：模型由 Ollama 下载，但用 CUDA 版 llama.cpp 读取同一批 GGUF 文件运行，性能比 Ollama 0.40.x 高 6–10 倍。文档给出按任务选择模型的决策表（Qwen3.6-35B-A3B 负责编程/Agent，Gemma 4 12B 负责快速多模态，TranslateGemma 4B 负责翻译）、12GB 显存的预算与共存矩阵、llama.cpp 关键调优参数、三种量化设置的区别，以及 Ollama 模型目录/端口/编码等排查方法。核心原则是“用对模型、一次只跑一个 llama-server、权重保持 Q4_K_M、KV cache 用 q8_0、按需开上下文与思考”。

### llama.cpp 关键调优参数

| 参数 | 作用 | 调整方向 |
|------|------|----------|
| `--n-cpu-moe 24` | Qwen 前 24 层专家放 CPU | 调小（20/16）更快但更吃显存；调大（28/32）更省显存但更慢 |
| `-ngl 999` | 尽量所有层放 GPU | 保持 999 |
| `-c 32768` | 上下文长度 | 显存不够降到 16384 / 8192；翻译 2048 |
| `-fa on` | Flash Attention | 保持开启 |
| `-ctk q8_0 -ctv q8_0` | KV cache 量化 | 省显存，质量几乎无损 |
| `--load-mode none` | 不用 mmap，直接加载 | 内存充足时保持 |
| `-t 16` | CPU 线程数 | 16 物理核；可试 12 / 20 |
| `--parallel 1` | 单用户 | 保持 1，省内存 |
| `--reasoning-budget 0` | 关闭思考 | 翻译/快速问答保持 0；复杂推理可去掉 |
| `--spec-type draft-mtp` | MTP 投机解码 | 大幅提速（45.6 → 64.8 tok/s），保持开启 |
| `--mmproj` | Gemma 视觉投影 | 图片输入必须；纯文本可去掉省显存 |

### 量化三层（不要混淆）

1. **权重量化（固定）**：模型文件内的 `Q4_K_M`，运行时不能改；是 12GB 显存的最佳平衡。Q8 太大（Qwen 35B Q8 约 39GB），Q2/IQ2 会明显降低质量和工具调用可靠性。
2. **KV cache 量化（可改）**：`OLLAMA_KV_CACHE_TYPE=q8_0`；显存不够时可用 `q4_0`；`f16` 质量最好但 12GB 不推荐。llama.cpp 对应 `-ctk q8_0 -ctv q8_0`。
3. **思考模式（不是量化）**：Qwen3.6 / Gemma 4 默认开启 thinking，会多花 token 和时间；Ollama 用 `--think=false`，llama.cpp 用 `--reasoning-budget 0`；复杂推理再打开。

### Ollama 运维要点

- `OLLAMA_MODELS=D:\Ollama\models`；应用 `settings.models` 也指向 D 盘（托盘程序会覆盖环境变量）
- `OLLAMA_CONTEXT_LENGTH=32768`、`OLLAMA_FLASH_ATTENTION=1`、`OLLAMA_KV_CACHE_TYPE=q8_0`
- 不要删除 `qwen3.6:35b-a3b-mtp-q4_K_M` / `gemma4:12b` / `translategemma:4b`，llama.cpp 启动脚本写死了 GGUF blob 路径
- 若重新拉取导致 hash 变化，用 `ollama show <模型名> --modelfile` 查新 `FROM` 路径并替换脚本 `-m`
- Windows junction 读取模型目录有 bug：应用 `settings.models` 指向真实目录，不走 junction

### 排查与验收

- OOM / 变慢：关 Index-tts2、ChatGPT/Codex、NVIDIA Broadcast；Qwen `--n-cpu-moe` 24→28 或 `-c` 32K→16K；翻译改 CPU
- GPU 没被用上：必须用 `D:\AI\llama.cpp\b12017\llama-server.exe`（CUDA 版），`--list-devices` 应显示 `CUDA0: NVIDIA GeForce RTX 5070 Ti Laptop GPU`
- 端口：Ollama 11434、Qwen 8081、Gemma 8082
- 中文乱码是终端编码问题，模型输出本身正确；用浏览器 UI 或 `chcp 65001`
- 音频：Gemma 4 图片输入已实测；音频 llama.cpp 支持不完整，建议先用 Whisper 转写
- 验收：Qwen ≥50 tok/s、Gemma ≥30 tok/s、翻译 GPU ≥70 tok/s、翻译 CPU ≥20 tok/s、TTS + 翻译 CPU 不 OOM、D 盘剩余 ≥20GB
