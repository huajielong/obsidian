# 摘要：向量数据库 vs 向量索引库

## 核心摘要

这份课程笔记澄清了一个 RAG 选型中极易混淆的差别：**[[Weaviate]] 是向量数据库，[[FAISS]] 和 [[Annoy]] 只是向量索引库**。

- **[[Weaviate]]**：同时存储向量、原始文本与元数据，支持 Dense 向量检索、BM25 关键词检索、Hybrid 混合检索、条件过滤、分页、持久化、内置 embedding 模型对接、多集合/权限/集群等数据库能力。
- **[[FAISS]]**：Meta 开源，向量搜索性能强、可承载海量向量，但索引中**只有向量**；原文、标题、元数据需要用户另外维护并手动按下标对齐。没有 BM25、过滤、查询语法和内置向量化。
- **[[Annoy]]**：Spotify 开源，适合小到中等规模向量，可保存/加载索引，同样**只存向量**；不支持复杂过滤和关键词检索，精度与大规模性能弱于 FAISS，但上手最简单。
- **[[Cohere]]**：只负责「文本 → 向量」的 embedding 生成，不负责存储与检索；生成的向量可以放进 Weaviate、FAISS 或 Annoy 任意一种。

**一句话**：Weaviate = 数据库（向量 + 原文 + 检索 + 过滤）；FAISS / Annoy = 向量检索工具盒（只管向量比对，其他全要自己写代码）。

## 关键对比

| 维度 | Weaviate | FAISS | Annoy |
|------|----------|-------|-------|
| 产品定位 | 完整向量数据库 | 向量索引库 | 向量索引库 |
| 存储内容 | 向量 + 原文 + 标题 + 元数据 | 仅向量 | 仅向量 |
| 向量检索 | ✅ Dense | ✅ 高性能 | ✅ |
| 关键词检索 | ✅ BM25 | ❌ | ❌ |
| 混合检索 | ✅ Hybrid | ❌ | ❌ |
| 条件过滤 / 分页 | ✅ | ❌ | ❌ |
| 持久化 | ✅ 重启后数据仍在 | ✅ 索引可写文件 | ✅ 索引可写文件 |
| 内置向量化 | ✅ 可对接 Cohere 等 | ❌ 需自己调用 embedding | ❌ 需自己调用 embedding |
| 元数据管理 | ✅ 数据库内建 | ❌ 用户自己维护列表/DataFrame | ❌ 用户自己维护列表/DataFrame |
| 适用规模 | 生产级 RAG、长期保存 | 百万级/海量向量、追求速度 | 小到中等规模、快速验证 |
| 上手成本 | 较重（独立服务进程） | 中等 | 最低 |

## 选型建议

- **课程演示 / 小数据集 / 只测试向量相似度** → [[Annoy]]
- **百万级向量 / 追求检索速度** → [[FAISS]]
- **RAG / 混合检索（BM25 + 向量）/ 条件过滤 / 不想自己维护元数据映射** → [[Weaviate]]
- **需要长期保存、重启不丢数据、带权限和集群** → 向量数据库（[[Vector_Database]]）

## 直观例子：课程 Articles 数据集

**Weaviate**：一条数据同时放 `text, title, url, lang, vector`，检索时可以直接 `where lang=en` 过滤。

**FAISS / Annoy**：

```python
# 向量索引里只存 vector
# 自己维护一份与下标对齐的元数据
meta = [
    {"text": "xxx", "title": "...", "lang": "en"},
    {"text": "yyy", "title": "...", "lang": "zh"},
]

ids, distances = index.search(query_vector, k)
results = [meta[i] for i in ids[0]]   # 手动用下标回查原文
```

过滤语言也要自己循环判断，索引和文字的对齐关系完全由应用层负责。

## 与 Cohere 的关系

Cohere 在整条链路中的职责只有一段：

```
文本 --Cohere Embedding--> 向量 --存入任意后端--> 检索
```

- Cohere embedding → Weaviate
- Cohere embedding → FAISS
- Cohere embedding → Annoy

Cohere 不存储原文、不做检索、不做过滤；它是一个 **embedding 提供方**，不是向量数据库。
