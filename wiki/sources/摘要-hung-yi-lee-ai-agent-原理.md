## 核心摘要

李宏毅《生成式AI時代下的機器學習(2025)》第二讲，用一堂课讲透 **AI Agent 的原理**。核心观点：AI Agent 就是"人类只给目标、不给步骤，AI 通过多步骤与环境互动自主达成目标"；把 LLM 直接当作 Agent 使用，本质是**利用 LLM 已有通用能力的一种应用，而非新的模型技术**——全程没有任何模型被训练。

讲座从三个面向剖析 Agent 的关键能力：

1. **根据经验调整行为**：不更新模型参数，而是通过 **Memory（Read/Write/Reflection 三模块）＋ RAG 检索**把相关经验放进上下文；StreamBench 实验发现"正面例子远优于负面例子"。
2. **使用工具**：通用做法是用 `Tool`/`Output` 标记让模型输出函数调用（Function Calling），工具说明可存入 Memory 做工具选择，模型还能自己写代码打造新工具；同时揭示"内部知识 vs 外部知识的角力"与"说服 AI"的研究。
3. **做计划**：模型可以显式产出计划（Plan）并依据计划行动，但环境不可预测需要 Replan；PlanBench/神秘方块世界/旅行规划评测显示规划能力"介乎有与没有之间"；Tree Search + World Model 的"脑内小剧场"（梦境模拟）是强化规划的可行方向，但也带来**过度思考**的新问题。

## 一、AI Agent 是什么

### 定义与运作循环

| 要素 | 说明 |
|------|------|
| **目标（Goal）** | 人类只给定目标，不给定具体行为/步骤 |
| **观察（Observation）** | Agent 观察当前环境状态 |
| **行动（Action）** | Agent 决定并执行动作，改变环境 |
| **循环** | 观察 → 行动 → 新观察 → 新行动，直到达成目标 |

- 以 AlphaGo 为例：目标=赢棋，observation=棋盘盘面，action=19×19 中选一个落子位置。
- 过去打造 Agent 靠 **RL 算法**（把目标转成 reward，训练模型 maximize reward），但局限是**每个任务都要单独训练一个模型**（AlphaGo 能下围棋不代表能下西洋棋）。
- 现在的思路转变：**直接拿 LLM 当 Agent**——用文字描述目标与环境，LLM 的"文字接龙"能力天然完成 observation→action 的映射，无需针对任务训练。

### 关键论点

> **AI Agent 不是 LLM 的新技术，而是 LLM 的应用。** 对 LLM 而言，它只是继续做文字接龙，输入不同（含目标、observation、工具调用），接出的内容就不同。

- **通用性优势**：LLM 输出近乎无穷（能说话、能写代码、能调工具），Agent 可采取的行动不再受限；而 AlphaGo 只能做 19×19 选择题。
- **无需定义 reward**：RL 的 reward 设计（为什么 compile error 是 -1 不是 -17.7？）靠"通灵"，而 LLM 能直接读懂 error log 这类丰富反馈。
- **历史脉络**：2023 年春第一波 Agent 热潮（AutoGPT 等）一度消退，因为实际能力与宣传有差距；如今因 LLM 变强而再次爆红。

### 定义辨析与课程立场

- "AI agent" 是被广泛使用的词汇，**每个人心里的定义可能都不一样**；李宏毅不争论哪种定义才是"真正"的 AI agent。甚至有人主张：只有像机器人那样**拥有身体（embodied）**的才算 AI agent，而用 LLM 驱动的"AI agent"都不是。
- 本课程立场：**AI agent = 人类只给目标、不给行为步骤，AI 通过多步骤与环境互动自主达成目标**；全程**没有任何模型被训练**，只靠现有 LLM 的文字接龙能力。

### LLM 自身的能力边界：下棋

- **BigBench 西洋棋（2022，ChatGPT 之前的上古时代）**：把棋盘转成文字喂给当时的语言模型，问"下一步走哪才能将军"——**没有任何模型给出正确答案**；但较强的模型至少走出符合规则的棋，较弱的模型则乱走、根本没搞懂规则。
- **ChatGPT o1 vs DeepSeek-R1 下棋视频（爆款，数百万观看）**：两方都违反规则——把兵当马用、主教无视阻挡、空降棋子吃子、DeepSeek 在己方棋盘变出一个城堡、用城堡吃掉自己的兵后宣布胜利（对方投降）。→ 最先进的 LLM 要下好棋还有距离，但这不妨碍它们作为 Agent 做其他事。

## 现实世界应用实例

### AI 村民（虚拟村莊，2023）

- **Generative Agents**（Stanford 2023）：虚拟村莊的 NPC 全部由语言模型驱动；每个 NPC 有一个人为设定的目标（办情人节派对、准备考试……）。
- 运行方式：观察环境（LLM 只能读文字，环境以文字描述，如"Eddy 正在读书、Elizabeth 正在装饰房间"）→ 决定行为（如"不早了，上床睡觉"）→ 由**转译器**把语言输出转成真正可执行的指令（走到床边、睡觉）。

### Minecraft 大规模 AI NPC

- 后续更大规模实验：把 Minecraft 的 NPC 全部换成 AI；根据影片描述，这些 AI NPC 宣称"组织了交易金融体系、成立政府、制定宪法自我管理"（真实性存疑）。

### 让 AI 使用电脑（Computer Use）

- 代表产品：**Claude Computer Use**、**ChatGPT Operator**（界面会建议"订 pizza""预约居家清洁"等）。目标=用户指令，observation=电脑屏幕画面（多模态 LLM 可直接看图），action=按哪个键/点哪个鼠标按钮。
- **历史脉络**：2017 年 **World of Bits**（预训练时代产物）用 CNN 直接吃屏幕、输出鼠标/键盘动作；2023 年夏一波 web agent（**Mind2Web / WebArena / Visual WebArena**）与今天的 Operator 非常像——给模型看屏幕画面或 HTML 代码，让它自己决定动作并解决问题（如订机票）。

### AI 训练 AI

- 作业二：目标=过 strong baseline，给 LLM 训练数据 → 它写程序训练模型 → 读正确率 → 再改程序……循环下去。
- 代表框架：**AIDE**（machine learning engineer agent，multi-agent 解数据科学竞赛）。

### AI 科研助手

- **Google AI Co-scientist**：用 AI 做研究，但**有局限——不能真做实验**，只能把研究想法整理成完整 Proposal；博客宣称"人类要花十年才能得到的成果，AI agent 花两天就得到"（生物学案例，真实性无法判断）。

## 语音即时互动（非回合制）

- 前面的 Agent 互动都是**回合制**（一个 observation → 一个 action → 新 observation……），但真实世界需要**即时响应**：action 还没执行完环境就变了，模型要能立刻切换行动。
- **语音对话是典型场景**：人类对话会互相打断、会有"嗯、对"这类没有语义但有"我在听"含义的回馈；AI 想做到人机语音对话像人人对话一样自然，就需要这种非回合制互动。
- **GPT-4o 高级语音模式（Advanced Voice Mode）** 某种程度上做到了即时互动——例子：让 AI 讲一个故事，AI 说"从前从前……"；此时人插话"好"（observation，不需要改变行为，故事继续）；人说"这不是我要听的故事"（observation，AI 应立即停下来换一个故事）。
- 参考阅读：**林冠廷**（实验室同学）与 Berkeley / UW / NIT 合作者写的文章，评测现有语音模型的"互动能力"，并对截至今年 1 月的可互动语音模型做了完整 survey。
- 顺带：讲义引用论文的原则——能找到 arXiv 链接就直接贴 arXiv（AI 领域变化太快，期刊/会议审稿周期跟不上，预印本已成习惯做法；arXiv 编号前两位=年份、后两位=月份）。

## 二、根据经验调整行为（Memory）

### 核心问题

- 不更新模型参数，模型怎么改变行为？**直接把错误/反馈信息放进输入**即可——同一模型，输入不同，接龙结果就不同。
- 但把"一生的经历"全塞进 Context 不可行（**超忆症**类比：记忆过长反而无法抽象思考、算力不足）→ 需要 **Memory**。

### Read / Write / Reflection 三模块架构

| 模块 | 职责 | 实现方式 |
|------|------|---------|
| **Read（读取）** | 从长期记忆中检索与当前 observation 相关的经验，放入输入前 | 本质是 **RAG 检索系统**（observation=query，memory=数据库），唯一区别是记忆来源是"自己的经历"而非全网 |
| **Write（写入）** | 判断哪些信息值得记入长期记忆 | 可以用 LLM（甚至 Agent 自己）自问"这件事重要吗"，重要的才写 |
| **Reflection（反思）** | 对记忆做高层抽象整理、建立记忆间关系 | 用 LLM 提炼新想法 / 建 **Knowledge Graph**（GraphRAG、HippoRAG 手法可套用） |

- **实例**：ChatGPT 的"记忆"功能就是 Write 模块启动（明确说"记下来"基本必触发）；它把对话内容"升华反思"后再存，所以可能存错（如把老师误记为学生）。
- **记忆研究方向脉络**：MemoryGPT（2023）→ Agent Workflow Memory（2024）→ Agent Memory Agent（2025）——23~25 年每年一篇代表，说明"Agent 记忆"是持续热门的研究方向。
- **实验证据（StreamBench）**：让 Agent 依序解一系列有标准答案的问题并利用过往反馈学习。
  - 使用 RAG 式检索（粉红线）正确率显著高于固定随机取 5 个例子（黄线）、远高于不学习（灰线）。
  - **正面例子 > 负面例子**：只给负面例子基本无帮助甚至有害；只给正面例子在所有数据集上都更好。→ "告诉模型要做什么"优于"告诉它不要做什么"。

## 三、使用工具（Tool Use）

### 通用方法：Prompt 驱动的 Function Calling

- **工具 = 函数**：模型不需要知道工具内部如何运作，只需知道输入输出接口 → 使用工具 = 调用函数（Function Calling）。
- **最通用做法（对所有能力较强的模型有效）**：在 System Prompt 中说明"工具描述放在 `Tool` 标记中间，工具输出放在 `Output` 标记中间"，再列出可用函数与调用范例。模型若需要工具，会输出 `Tool` 包裹的调用文本；开发者写胶水脚本把这段文本转成真实函数调用，把返回塞进 `Output`，模型继续接龙完成回答。
- **System Prompt vs User Prompt**：System Prompt 是开发者设定的、每次相同的最高优先级指令；User Prompt 是用户输入。冲突时模型听 System Prompt 的。

### 工具相关的关键洞察

| 洞察             | 内容                                                                |
| -------------- | ----------------------------------------------------------------- |
| **工具选择**       | 工具很多（上百上千）时不能全读说明，用"工具选择模块"（类似 RAG）根据当前状态从工具库挑出合适的                |
| **模型自建工具**     | 模型能自己写代码（写函数），成功后把函数放入工具库复用——与"把成功经验写入 Memory"本质相同                |
| **搜索 = 最常用工具** | 用搜索引擎 = RAG（Retrieval Augmented Generation）                       |
| **模型不完全相信工具**  | 内部知识（参数里的 internal knowledge）与外部知识（工具输出）会"角力"；极端不合理输出（一万度）会被模型识破  |
| **说服 AI 的研究**  | 外部知识与模型信念差距越小越容易被相信；模型倾向相信"AI 同类"写的文章；相信更新发布（metadata）的文章；文章来源影响小 |
| **工具不一定更高效**   | 简单问题（3×4）人类心算快于按计算器；早年调翻译/问答工具的方案今天已无必要——是否用工具取决于模型自身能力           |
| **工具的信任问题**     | Google AI Overview（RAG）曾建议"起司黏不住就用无毒胶水粘上去"——源自 Reddit 乡民的玩笑，模型无法分辨玩笑与事实 → 要提醒"工具的工具"别全信；但模型也有一定判断力：给气温"100 度/1 万度"的荒谬工具输出，它能识破后者有问题                          |
| **说服 AI 的研究**     | 药物剂量实验：模型内知 20mg vs 报告 30mg；把报告改为 3mg（÷10）→ 不信；60mg（×2）→ 信；300mg（×10）→ 又不信 → **外部知识与模型内部信念差距越小越容易被相信**；模型对答案信心低时更容易被动摇；两篇观点相反的文章，模型倾向信 **AI 写的**（即使 AI 观点与模型自己不同）；文章的 **metadata（发布时间）** 影响判断——**越新的文章越容易被相信**（来源影响小）；同内容好看的排版也会被偏好（仅 2 种模板实验，不宜过度推广） |
| **RAG 不是万能**       | 即使工具/搜索结果正确，模型仍可能犯错：旧版 ChatGPT 搜"介绍李宏毅"时把演员李宏毅与台大教授李宏毅**混成一个人**介绍（现版本已修复） |

### 案例：文字模型 + 语音工具（Dynamic-SUPER）

- 文字模型本身不能"听"语音，但可以通过工具使用一组**语音相关工具**（语音辨识 ASR / 说话人验证 / 声音分类 / 情绪辨识……）来间接理解音频，最后再调一个 LLM 汇总答案——例如回答"这个人讲了什么、心情如何、背景杂音显示他在哪"。
- 在 **Dynamic-SUPER**（衡量语音版语言模型能力的 benchmark，55 个语音相关任务）上，这个"让文字模型使用工具"的方法（大助教的工作）平均正确率**完胜**当时所有号称"原生能听语音"的模型。

## 四、做计划（Planning）

- **显式计划**：看到第一个 observation 时，让模型产出达到目标的系列行动（计划），把计划放进输入，后续 action 依据计划执行。
- **规划能力的表象与历史**：让 LLM 制定"成为百万订阅 YouTuber"的计划，它会给出分阶段合理规划（定位→10 万→50 万→百万），这类"農場文"常被用来吹嘘模型规划能力，但可能只是照本宣科；2022 年（史前时代）论文曾让 Codex12B 把"刷牙""拿牛奶喝"分解成步骤序列并在虚拟世界执行，看起来也有一定规划能力——但这类训练数据常见的内容不能证明模型真正理解"规划"。
- **计划会被打破**：行动→观察由外部环境决定，环境有随机性（对手的招数、弹出的广告窗口）→ 需要**每次看到新 observation 后 Replan**。
- **评测现状**：
  - **PlanBench**（叠积木）：普通 Blocksworld 模型能解；**神秘方块世界**（奇怪的规则）防止模型"照本宣科"，2023 年 GPT-4 仅 ~9%，2024 年 o1 系列 reasoning 模型有希望解决。
  - **旅行规划（TravelPlanner 类）**：2024 年初纯 LLM 成功率约 0%（GPT-4 Turbo 0.6%），把约束交给**现成 solver 当工具**后可达 90%+。
  - 结论：模型规划能力"**介乎有与没有之间**"。
- **强化规划**：
  - **Tree Search**：与真实环境交互穷举所有路径代价高 → 自问自答"这条路径还有希望吗"并剪枝（Tree Search for Language Model Agents）；缺点是一些动作**覆水难收**（pizza 已订）。
  - **World Model / 梦境模拟**：在"脑内小剧场"中让模型自己扮演环境（World Model），用文字描述行动后果，评估各路径成功率后只在实际世界执行最优一步——"is your LLM secretly a world model of the internet"。
  - **Reasoning 模型**：会思考的模型（能演脑内小剧场）做 Agent 整体更好，但带来 **Over-Thinking（过度思考）** 问题——"思考的巨人、行动的矮子"，想太多而不行动（"The Danger of Overthinking"）。
