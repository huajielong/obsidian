# 向量索引库（Vector Index）

## 定义

向量索引库是**只负责向量相似度搜索**的工具/库：它接收向量、构建近似最近邻（ANN）索引、返回最相近的向量下标或距离，但**不保存原始文本和业务元数据**，也不提供数据库查询、过滤、权限等能力。

> 它与[[Vector_Database|向量数据库]]的分界不在「能不能搜向量」，而在「搜完之后能不能直接拿到原文、元数据和过滤结果」。

## 核心特征

| 特征 | 说明 |
|------|------|
| **只存向量** | 索引内部只有向量与下标，没有 text/title/url 等字段 |
| **纯相似度检索** | 输入查询向量，返回 top-k 下标与距离 |
| **索引持久化** | 可将索引写入本地文件，下次加载继续用 |
| **无 BM25** | 不支持关键词/字面检索 |
| **无 where 过滤** | 语言、时间、标签等条件需应用层自己处理 |
| **无查询语言** | 没有数据库式查询语法 |
| **无内置向量化** | 需先调用 [[Cohere]]、OpenAI 等生成向量再喂入 |

## 元数据映射：使用索引库的核心成本

索引库只返回下标，原文要自己维护一份与下标严格对齐的元数据列表：

```python
meta = [
    {"text": "第一篇原文", "title": "A", "lang": "en"},
    {"text": "第二篇原文", "title": "B", "lang": "zh"},
]

ids, distances = index.search(query_vector, k)
results = [meta[i] for i in ids[0]]
```

如果还要按语言过滤，需要自己在 `results` 上循环判断，或先筛选候选再检索。**下标一旦错位，返回的原文就会整体串行**——这是索引库方案最常见的事故来源。

## 代表实现

| 库 | 开发者 | 适用规模 | 特点 |
|----|--------|---------|------|
| [[FAISS]] | Meta | 百万级/海量向量 | 检索性能强，索引类型丰富，生态成熟 |
| [[Annoy]] | Spotify | 小到中等规模 | API 最简单，`save()`/`load()` 持久化，精度与规模弱于 FAISS |

## 什么时候选索引库

- **只想快速验证向量相似度**：[[Annoy]]
- **百万级向量、追求检索速度**：[[FAISS]]
- **已有自己的原文存储与过滤逻辑**：FAISS/Annoy 只当检索内核
- **不需要 BM25、条件过滤、长期数据库管理**：索引库足够

## 什么时候不该选

- 需要 BM25 + 向量混合检索
- 需要 `where lang = "en"` 之类的条件过滤
- 需要重启后原文与元数据仍然完整可用
- 不想维护「向量下标 ↔ 原文」的映射关系

以上场景应直接使用[[Vector_Database|向量数据库]]。

## 持久化 API 备注

- **FAISS**：索引持久化使用 `faiss.write_index(index, path)` / `faiss.read_index(path)`；来源笔记中写作 `index.save()`，实际以 FAISS 官方 API 为准。
- **Annoy**：使用 `AnnoyIndex.save(path)` / `AnnoyIndex.load(path)`。
