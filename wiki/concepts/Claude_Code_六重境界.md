## 定义

Claude Code 六重境界是由视频作者 云桥网络 提出的 Claude Code 技能进阶框架，将用户从入门到精通的成长路径划分为六个递进层次。每层境界对应一组核心技能、思维转变和需要规避的陷阱，从基础的提示词工程到高级的多 Agent 规模化编排。

## 六层境界概览

| 层级 | 名称 | 核心能力 | 关键转变 |
|:----:|------|---------|---------|
| L1 | **提示工程师** | 编写清晰提示词、评判输出质量、基本终端知识 | 从"命令工具"到"开始协作" |
| L2 | **规划者** | 计划模式、协作式提问、对抗性审查 | 从"单向指令"到"双向互动" |
| L3 | **上下文工程师** | 上下文窗口管理、腐败控制、CLAUDE.md 优化 | 从"纯文字指令"到"引入外部上下文" |
| L4 | **MCP/工具集成** | 理解系统构建模块、外科手术式选配工具 | 从"盲点生存"到"理解技术全景" |
| L5 | **技能/工作流** | Skill 编写与组合、工作流封装 | 从"重复操作"到"流程产品化" |
| L6 | **规模化编排** | 多会话协调、Git Worktrees、子代理、Agent Teams | 从"单实例"到"多实例管理者" |

## 各层详解

### L1 · 提示工程师（Prompt Engineer）

最基础的入门层。用户将 Claude Code 视为简单的指令执行工具，采用单向命令式交互。此阶段的典型输出被描述为"回归平庸"（Regression to the Mean）——AI 产出千篇一律、缺乏个性。

**核心技能**：
- 撰写清晰具体的提示词（明确目标、子功能、成功标准）
- 阅读和评判 AI 生成的内容，能识别"AI 垃圾"
- 基本终端使用知识（文件权限、依赖关系、Bash 命令含义）

**常见陷阱**：将 Claude Code 当作钝器工具而非合作者，导致产出平庸。

### L2 · 规划者（Planner）

从单向指令转向双向协作。用户启用计划模式（Plan Mode），与 Claude Code 共同规划和讨论方案。

**核心技能**：
- 熟练使用计划模式（Plan Mode）
- 协作式提问："我是不是漏掉了什么？"、"可能有什么意想不到的后果？"
- 要求 Claude Code 扮演对抗性角色，对构思提出挑战
- 创建"魔鬼代言人"子智能体审查方案

### L3 · 上下文工程师（Context Engineer）

引入外部上下文（文件、截图、具体事例）来提升交互质量。上下文窗口管理是此层的"王牌技能"。

**核心技能**：
- 理解上下文腐败（Context Corruption）机制：模型效率会在窗口填充到 50-60%（约 100k-120k tokens）后突然下降，此阈值不随窗口扩大而移动
- 使用 `/clear` 命令主动重置上下文窗口
- 正确使用 CLAUDE.md 文件（少即是多，避免过度填充）
- 了解 `/compact` 的局限性——自动压缩可能导致信息丢失
- 创建常驻状态栏（HUD）实时观察上下文窗口使用量
- 区分"Claude Code 真正需要的上下文"与"帮倒忙的上下文"

### L4 · MCP/工具集成（MCP/Tool Integrator）

接触和集成外部能力——MCP 服务器、框架、各类插件。核心挑战是避免"糖果店孩子"综合征——看到所有工具都想装。

**核心技能**：
- 理解基本的系统构建模块（前端/后端/认证/数据库/部署/安全）
- 让 Claude Code 解释其工作原理和工作方式
- 外科手术式精准选配 MCP 和工具，而非盲目堆积所有可选项
- "能力 ≠ 性能"——明确能力提升与实际性能改善之间的区别

### L5 · 技能/工作流（Skills/Workflow Creator）

将重复性工作流封装为可重用的 Skills。此层让 Claude Code 真正成为用户的"专属工具"。

**核心技能**：
- Skill 编写能力——清晰描述工作流程让 Claude Code 理解
- 使用 Skill Creator 插件进行评估和基准测试
- 技能的层级组合（Skill A 调用 Skill B，技能叠套）
- 按项目本地化配置 Skills，而非全局堆积
- 利用技能组合器确认组合技能是否可用或需要优化

### L6 · 规模化编排（Scale Orchestrator）

同时协调多个 Claude Code 实例，化身为"管理者"角色。包含四种递进的扩展方式。

**四种扩展方式**：
1. **多终端会话**：同一项目打开多个 Claude Code 实例并行工作，手动协调任务分配
2. **Git Worktrees**：每个实例在独立的工作副本上操作，避免合并冲突，最后统一合并
3. **子代理自动化**：主终端通过子代理在多个 Worktree 上分配任务，抽象封装底层细节
4. **代理团队（Agent Teams）**（实验性功能）：子代理之间可互相通信协作，自动产生"主管"角色协调分工，通过多色标识区分各代理状态

## 核心思维转变

六层境界贯穿的核心主线是从 **"AI 工具使用者"** 到 **"AI 协作者"** 的思维转变。每层晋级都要求用户更主动地掌握主导权、更深入地理解技术原理、更精细地管理交互过程。视频强调：很多时候用户不知道"自己不知道什么"，这正是卡在某层无法前进的根本原因。
