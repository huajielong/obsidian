# 向量数据库（Vector Database）

## 定义

向量数据库是**以向量相似度检索为核心，同时提供数据库级数据管理能力**的系统：它不仅保存向量并支持近邻搜索，还负责原文、标题、元数据、过滤、分页、持久化，通常还集成 embedding 模型并支持多集合、权限与集群部署。

> 判断标准：如果它只回答「哪个向量离查询向量最近」，它是[[Vector_Index|向量索引库]]；如果它还能回答「这条向量的原文是什么、lang 是不是 en、第 2 页第 10 条是谁」，它才是向量数据库。

## 核心能力

| 能力 | 说明 |
|------|------|
| **向量存储与索引** | 保存 embedding，并构建 HNSW/IVF 等近似最近邻索引 |
| **原文与元数据存储** | 同一对象中保存 text、title、url、lang、views 等字段，检索后直接取回 |
| **Dense 检索** | 基于向量相似度的语义检索 |
| **BM25 关键词检索** | 字面匹配，弥补纯向量检索对数字、代码、专有名词的不足 |
| **Hybrid 混合检索** | 融合 Dense 与 BM25 的分数（常见 RRF） |
| **条件过滤 / 分页** | 如 `where lang = "en"`，在数据库层完成筛选与分页 |
| **持久化** | 服务重启后数据仍在，适合长期知识库 |
| **内置向量化** | 可直接对接 Cohere、OpenAI 等 embedding 模型 |
| **多集合 / 权限 / 集群** | 多租户、RBAC、副本与水平扩展等生产级能力 |
| **RAG 就绪** | 检索结果可直接作为 context 拼进 Prompt |

## 与向量索引库的分界

| 维度 | 向量数据库（[[Weaviate]] 等） | 向量索引库（[[FAISS]] / [[Annoy]]） |
|------|------------------------------|-----------------------------------|
| 存储对象 | 向量 + 原文 + 元数据 | 仅向量 |
| 检索方式 | Dense / BM25 / Hybrid | 仅向量相似度 |
| 过滤与分页 | 数据库内建 | 需应用层自己实现 |
| 元数据对齐 | 自动 | 手动维护 `meta` 列表并按索引下标回查 |
| 持久化 | 数据整体持久化 | 索引文件持久化，原文需另行保存 |
| 部署形态 | 独立服务进程（可 embedded） | Python/C++ 库 |
| 适用场景 | 生产 RAG、长期知识库、混合检索 | 海量向量、纯相似度搜索、快速实验 |

## 代表实现

| 系统 | 类型 | 特点 |
|------|------|------|
| [[Weaviate]] | 向量数据库 | 原文/元数据、BM25、Hybrid、过滤、持久化、RAG 集成 |
| Chroma | 向量数据库（轻量） | 上手快，适合本地原型 |
| Qdrant | 向量数据库 | 生产级过滤与负载能力 |
| Milvus | 向量数据库 | 大规模分布式部署 |
| pgvector | PostgreSQL 扩展 | 已有 Postgres 环境时无缝接入 |
| [[FAISS]] | 向量索引库 | Meta 开源，海量向量、极致检索性能 |
| [[Annoy]] | 向量索引库 | Spotify 开源，小到中等规模、最简单 |

## 选型决策

```
只做向量相似度搜索？
├─ 是 → 数据规模？
│       ├─ 小到中等 / 课程演示 → Annoy
│       └─ 百万级 / 追求速度 → FAISS
└─ 否 → 需要原文、元数据、BM25、Hybrid、过滤、持久化？
        └─ 是 → 向量数据库（Weaviate / Qdrant / Milvus / pgvector ...）
```

**关键提醒**：需要长期保存、重启不丢、带条件过滤或混合检索时，不要用 FAISS/Annoy 硬扛——应用层要补的元数据映射、过滤和持久化逻辑，往往比直接用一个向量数据库更贵。
