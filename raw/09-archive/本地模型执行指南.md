## 3. 显存预算与共存

12GB 总显存，Windows/桌面约 0.5–1GB。

| 组合 | 显存估算 | 是否可行 |
|---|---|---|
| Qwen 单独 | 10.8GB | ✅ |
| Gemma 单独 | 7.9GB | ✅ |
| TranslateGemma GPU 单独 | 3.6GB | ✅ |

- 查看占用：
  ```bat

  ```

## 4. 性能调优参数（llama.cpp）

脚本里的参数不是随便写的，下面是对应的调节方法：

| 参数 | 作用 | 调大 / 调小的影响 |
|---|---|---|
| `--n-cpu-moe 24` | Qwen 前 24 层专家放 CPU | **调小**（20/16）：更多专家上 GPU，更快，更吃显存；**调大**（28/32）：更省显存，更慢 |
| `-ngl 999` | 尽量把所有层放 GPU | 保持 999 |
| `-c 32768` | 上下文长度 | 显存不够时降到 16384 / 8192；翻译用 2048 |
| `-fa on` | Flash Attention | 保持开启 |
| `-ctk q8_0 -ctv q8_0` | KV cache 量化 | 省显存，质量几乎无损；不要用 f16 除非显存富余 |
| `--load-mode none` | 不用 mmap，直接加载 | 本机实测更快；内存充足时保持 |
| `-t 16` | CPU 线程数 | 16 物理核；可试 12 / 20 |
| `--parallel 1` | 单用户 | 保持 1，省内存 |
| `--reasoning-budget 0` | 关闭思考 | 翻译/快速问答保持 0；复杂推理可去掉 |
| `--spec-type draft-mtp` | Qwen 的 MTP 投机解码 | 大幅提速（45.6 → 64.8 tok/s），保持开启 |
| `--mmproj` | Gemma 视觉投影 | 图片输入必须；纯文本可去掉省一点显存 |

**调优流程：**
1. 先保证能加载、不 OOM。
2. 只改一个参数，重启，测同一段话。
3. 观察 `nvidia-smi` 和 llama-server 输出的 tok/s。
4. 目标：显存留 0.5–1GB 余量，速度稳定。

**GPU 频率/功耗：**
- 实测生成时 GPU 约 1.1–1.2GHz、50W，未撞功耗墙，但也没有满频。
- 插电使用；在厂商 Control Center 或 NVIDIA App 里切到“性能 / 狂暴 / 最高性能”模式，可能再提升。
- 关闭 NVIDIA Broadcast 等后台 GPU 程序。

## 6. 常见问题排查

### 6.1 `ollama list` 为空 / 报 `bad manifest`

Ollama 0.40.x 在 Windows 上读取经过 junction 的模型目录有 bug。当前已修复：应用 `settings.models` 指向 `D:\Ollama\models`，不走 junction。

如果复发：
1. 完全退出 Ollama（托盘 Quit）。
2. 备份 `%LOCALAPPDATA%\Ollama\db.sqlite`。
3. 用 SQLite 把 `settings.models` 改回 `D:\Ollama\models`。
4. 重启 Ollama，确认 `server.log` 里 `OLLAMA_MODELS:D:\Ollama\models`。

### 6.2 OOM / 速度突然变慢

- 关闭 Index-tts2、ChatGPT/Codex、NVIDIA Broadcast。
- Qwen：把 `--n-cpu-moe 24` 改成 `28`；或把 `-c 32768` 改成 `16384`。
- Gemma：把 `-c 32768` 改成 `16384`。
- 翻译：改用 `translategemma-cpu`。
- 确认没有两个 llama-server 同时跑。

### 6.3 GPU 没被用上

- 必须使用 `D:\AI\llama.cpp\b12017` 里的 `llama-server.exe`（CUDA 版）。
- 启动脚本已把 `cuda_v13` 加进 PATH；不要删 Ollama 的 `lib\ollama\cuda_v13` 目录。
- 检查：`D:\AI\llama.cpp\b12017\llama-server.exe --list-devices` 应显示 `CUDA0: NVIDIA GeForce RTX 5070 Ti Laptop GPU`。
- Ollama 自带的 `lib\ollama\llama-server.exe` 是 CPU-only，不能用来跑 GPU。

### 6.4 端口冲突

- Ollama：11434
- Qwen：8081
- Gemma：8082
- 启动脚本会先 `taskkill llama-server.exe`；如果还有冲突，双击 `stop-llama.bat`。

### 6.5 中文显示乱码

- 这是终端编码问题，模型输出本身是正确的。
- 用浏览器界面（8081/8082），或用 UTF-8 文件输出，或 `chcp 65001`。

### 6.6 音频

- Gemma 4 的图片输入已实测可用；音频输入 llama.cpp 支持尚不完整。
- 需要音频时，建议先用 Whisper（faster-whisper / whisper.cpp）转写成文字，再交给模型。

### 6.7 下载慢 / 中断

- Ollama 支持断点续传，不要中途关机。
- 国内网络慢时挂代理；模型目录保持 D 盘，注意剩余空间。

## 7. 性价比建议

1. **用对模型，而不是都用最大模型**：
   - 翻译用 4B 专用模型（78 tok/s，3.6GB），不要用 35B。
   - 快速问答/图片用 Gemma 12B。
   - 只有编程/Agent/复杂推理才用 Qwen 35B。
2. **一次只跑一个 llama-server**：12GB 显存放不下两个大模型。
3. **TTS 和翻译同时跑时，翻译走 CPU**：0 显存、22 tok/s，足够。
4. **上下文按需开**：翻译 2K，日常 8K–16K，编程 32K；32K 会占更多 KV cache。
5. **保持 Q4_K_M**：Q8 更慢、更吃显存，收益很小。
6. **保持 D 盘 ≥20GB 空闲**：当前 D 盘约 72GB 可用。
7. **需要 TTS + 聊天**：可另装一个小通用模型（如 `qwen3.5:4b`，约 3.4GB，关思考），但会和 TTS 抢约 3.4GB 显存，不如翻译 CPU 版稳。

## 10. 模型量化与推理模式（最大性能设置）

### 10.1 五个模型的量化与能力

| 模型 | 架构 / 参数 | 量化 | 原生上下文 | 能力 | 用途 |
|---|---|---|---|---|---|
| `qwen3.6:35b-a3b-mtp-q4_K_M` | qwen35moe / 35.5B | Q4_K_M | 262144 | 文本、图片、tools、thinking | 主力编程 / Agent / 中文 |
| `gemma4:12b` | gemma4 / 11.9B | Q4_K_M | 262144 | 文本、图片、音频、tools、thinking | 快速多模态 |
| `translategemma:4b` | gemma3 / 4.3B | Q4_K_M | 131072 | 文本、图片 | 翻译基础模型 |
| `translategemma-2k` | gemma3 / 4.3B | Q4_K_M + num_ctx 2048 | 2048（实际） | 文本、图片 | 翻译 GPU 版 |
| `translategemma-cpu` | gemma3 / 4.3B | Q4_K_M + num_ctx 2048 + num_gpu 0 | 2048（实际） | 文本、图片 | 翻译 CPU 版 |

### 10.2 三种设置不要混淆

1. **权重量化（模型文件，固定）**
   - `Q4_K_M` 已经写进模型文件，运行时不能改。
   - Q4_K_M 是 12GB 显存的最佳平衡：质量接近 Q5/Q6，速度和显存占用都合适。
   - 不要用 Q8：Qwen 35B Q8 约 39GB，太慢/放不下；Gemma 12B Q8 约 12.8GB，加 KV cache 会 OOM。
   - 不要用 Q2/IQ2：质量和工具调用可靠性明显下降，不适合 Agent。
   - 查看当前量化：`ollama show <模型名>`。
   - 想换权重量化：只能拉取/创建另一个已经量化好的模型；不能把 Q4 模型“升”成 Q6 来恢复质量。

2. **KV cache 量化（运行时，可改）**
   - `OLLAMA_KV_CACHE_TYPE=q8_0`（当前设置）：省显存、几乎无损，推荐。
   - `q4_0`：更省显存，轻微质量损失；显存不够时用。
   - `f16`：质量最好但最占显存，12GB 不推荐。
   - llama.cpp 对应参数：`-ctk q8_0 -ctv q8_0`（启动脚本已设置）。

3. **思考模式（thinking，不是量化）**
   - Qwen3.6 / Gemma 4 默认开启 thinking，会多花 token 和时间。
   - 关闭提速：Ollama 用 `--think=false`；llama.cpp 用 `--reasoning-budget 0`（启动脚本已设置）。
   - 复杂推理再打开；翻译和快速问答建议关闭。

### 10.3 每个模型的最大性能配置

| 模型 | 运行时 | 关键设置 | 实测速度 | 显存 |
|---|---|---|---|---|
| Qwen3.6 | llama.cpp 8081 | `--n-cpu-moe 24 -ngl 999 -c 32768 -fa on -ctk q8_0 -ctv q8_0 --load-mode none -t 16 --parallel 1 --reasoning-budget 0 --spec-type draft-mtp` | 约 65 tok/s | 10.8GB |
| Gemma 4 12B | llama.cpp 8082 | `-ngl 999 -c 32768 -fa on -ctk q8_0 -ctv q8_0 --load-mode none -t 16 --parallel 1 --reasoning-budget 0 --mmproj` | 约 34 tok/s | 7.9GB |
| TranslateGemma GPU | Ollama `translategemma-2k` | Q4_K_M、2048 ctx、q8_0 KV | 约 78 tok/s | 3.6GB |
| TranslateGemma CPU | Ollama `translategemma-cpu` | Q4_K_M、2048 ctx、`num_gpu 0` | 约 22 tok/s | 0GB |

### 10.4 调参口诀

- **权重保持 Q4_K_M**；KV cache 用 q8_0；编程 32K，翻译 2K；不需要思考就关闭。
- Qwen 的 `--n-cpu-moe 24` 是甜点：调小（16–20）更快但更吃显存；调大（28–32）更稳但更慢。
- 显存不够：先调大 `--n-cpu-moe`，再降上下文，再关后台程序。
- 想真正发挥性能：大模型用 llama.cpp，不要用 Ollama 跑 Qwen/Gemma；Ollama 只用于翻译和小模型。
- 后台程序（Index-tts2、ChatGPT/Codex、NVIDIA Broadcast）会占 4–6GB 显存，用大模型前必须关闭。
